# 37 Barbershop — изолированная демоверсия Workers + D1

Неофициальная закрытая демонстрация. Реальные записи и приём настоящих контактов отключены на сервере. Исходная версия FastAPI/Render в корне репозитория сохранена.

## Локальный запуск

Нужны Node 24 и pnpm 11. Устанавливать из этого каталога:

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm db:local
pnpm seed:local
pnpm dev
```

Открыть http://127.0.0.1:8787. Каталог доступен для просмотра. Защищённые действия требуют действительной подписи Telegram и включения ID в DEMO_USER_IDS. Токены в проекте отсутствуют.

Для проверки Telegram заполнить **локальную** `.dev.vars` на основе `.dev.vars.example`; в облаке использовать Secrets. Отдельный тестовый бот удобен, но необязателен. Для проверки через @ArminaHair_Bot нужны только разрешённые тестировщики и отдельная кнопка новой версии в личном чате. Не менять его действующий webhook или публичное меню без отдельного разрешения. OWNER_IDS задаёт владельцев; DEMO_USER_IDS — разрешённых тестировщиков. Пользователь может одновременно быть владельцем и привязанным мастером. При блокировке/архивировании мастера его привязка Telegram очищается.

### Браузерная проверка без настоящего Telegram

BOT_TOKEN, OWNER_IDS и DEMO_USER_IDS не объявлены публичными vars в wrangler.jsonc: задавайте их как Cloudflare Secrets, чтобы deploy не перезаписывал закрытый список пустыми значениями. Вход владельца через текущего бота подтверждён пользователем. Это не подтверждает обработку /start новым Worker при сохранённом Render webhook.

```sh
node scripts/prepare-assets.mjs
pnpm exec wrangler d1 migrations apply barbershop-37-demo --local --config tests/wrangler.ui.jsonc --persist-to .wrangler/ui-proof
pnpm exec wrangler d1 execute barbershop-37-demo --local --config tests/wrangler.ui.jsonc --persist-to .wrangler/ui-proof --file seeds/demo.sql
pnpm exec wrangler dev --local --config tests/wrangler.ui.jsonc --persist-to .wrangler/ui-proof --port 8788
```

Это отдельный локальный тестовый entrypoint с вымышленным Telegram ID 1 и несуществующим токеном. Он генерирует подписанный тестовый контекст, а API проходит обычную HMAC-проверку. **Не разворачивать tests/wrangler.ui.jsonc в облаке.** Основная конфигурация использует только `src/index.ts`; тестовый bootstrap не попадает в её сборку. Браузерные тесты не доказывают доставку настоящих сообщений Telegram.

## Что реализовано

- Hono/TypeScript, Workers Static Assets, SQL-миграции D1, настройки и журнал изменений.
- Каталог из 8 услуг; фиксированные цены/диапазоны; снимок цены, названия и длительности визита.
- Серверная подпись Telegram initData, срок 1 час, закрытый список демоучастников, роли клиента/мастера/владельца.
- Добавление/редактирование мастеров, архив/восстановление, предупреждение о будущих визитах, отзыв доступа; одноразовые приглашения через защищённый webhook.
- Общий прайс владельца и индивидуальная длительность мастера; права мастера ограничены собственным профилем.
- Онлайн- и ручные тестовые записи, любой свободный мастер, перенос/отмена, завершение/неявка, итоговая цена и дополнительное время без изменения прайса.
- Разделённые рабочие интервалы и отсутствие/отпуск. Изменения, нарушающие существующие записи, откатываются транзакционно.
- Исключения графика по датам: другие часы или выходной заменяют недельное расписание. Контроль версий защищает от потери параллельных изменений; конфликтующий переход обратно к недельному графику отклоняется.
- Общие/персональные ссылки, фактический предварительный выбор доступного мастера, QR PNG и копирование ссылки в кабинетах. При пустом MINI_APP_URL явно предлагается браузерный предпросмотр. После настройки проверенного прямого адреса Mini App QR использует Telegram startapp; параметр запуска не даёт прав доступа.
- Ограничение 1 будущей онлайн-записи для нового клиента / 2 после завершённого визита; ручные записи не используют этот лимит.
- Приватные заметки в контексте мастера и его клиента.
- Календарь владельца/мастера с периодом до 31 дня, фильтрами по мастеру/статусу, историей архивных профилей и курсорными страницами по 100 визитов. Права мастера ограничены сервером.
- Список клиентов владельца с пагинацией, историей завершений/неявок и блокировкой новых онлайн-записей. Изменение доступа проверяет прежнее состояние, пишет аудит и сохраняет существующие визиты.
- Таблица уведомлений, ограниченные повторные попытки, аренда задания при параллельном Cron, напоминания 24ч/2ч, обработка 403/429. Абсолютная однократная доставка при сетевой неопределённости не гарантируется.
- Армянский по умолчанию, переключение на русский, мобильное тёмное оформление и предупреждение о демо.

## Как защищены интервалы

Обычная проверка «свободно → вставить» не используется как гарантия целостности. SQLite-триггеры **внутри операции D1** проверяют полный полуоткрытый интервал `[starts_at, ends_at)`, график, отсутствие и лимит клиента. Пересекающиеся записи одного мастера или клиента отклоняются. Соседние интервалы разрешены.

Создание клиента, записи, уведомлений и аудита выполняется одной D1 batch. При конфликте откатывается весь batch. Цена копируется через INSERT SELECT из каталога; дальнейшие изменения каталога не переписывают историю. Идемпотентность — UNIQUE(created_by, idempotency_key) плюс хеш нормализованного запроса. Повтор с другим содержимым возвращает 409. Перенос сохраняет исходную длительность и защищён номером версии.

График заменяется одной batch с последующей проверкой всех будущих визитов. CHECK-ограничение в служебной таблице откатывает замену, если хотя бы один визит оказался вне графика. Параллельная вставка записи/изменение графика сериализуются самой D1.

## Облачная конфигурация — тестовый каталог развёрнут

Адрес: https://barbershop-37-demo.barbershop-37.workers.dev. Основной `src/index.ts` размещён отдельным Worker, `DB` привязан к отдельной D1 `barbershop-37-demo`. `workers_dev: true`, `preview_urls: false`. Токен и webhook secret не заданы; списки участников/владельцев и BOT_USERNAME пустые. Открыт только просмотр тестового каталога; создание визитов и кабинеты требуют Telegram и разрешённого ID. Действующий @ArminaHair_Bot не подключён.

Дата совместимости закреплена на `2026-10-13`, поддерживаемой локальным runtime закреплённого Wrangler 4.150.0 и облаком. Первоначальная дата `2026-10-22` была отвергнута облаком, а промежуточная `2026-10-20` не поддерживалась этим локальным бинарником. Это версия поведения runtime, а не дата визита или часовой пояс салона.

`pnpm dev`, `pnpm test`, `pnpm build` и `pnpm run deploy` сначала создают QR-модуль из закреплённого npm-пакета. Папка public/vendor не хранится в Git; не запускать голый wrangler deploy после чистого checkout без подготовки assets. Лицензия библиотеки доступна в public/THIRD_PARTY_LICENSES.txt.

Блок графика по датам и QR размещён отдельным обновлением: версия Worker `16027195-88af-4242-88fa-0f054558366a`, миграция `0003_date_schedules.sql`. Перед миграцией сделан свежий удалённый экспорт. После неё 8 услуг/3 вымышленных мастера/0 визитов сохранились; 8 триггеров, quick_check=ok, foreign_key_check пустой. Экспорт удалённой D1 восстановлен в отдельную `barbershop-37-restore-check`: 8 услуг, 3 мастера, 0 визитов, 5 триггеров; quick_check=ok, foreign_key_check пустой. Реальные Telegram-сценарии, доставка уведомлений, Time Travel и нагрузка/CPU пока не проверены.

Порядок для отдельного нового аккаунта и оставшейся настройки:

1. Авторизовать официальный Wrangler в своём аккаунте.
2. Создать **отдельную** бесплатную D1 и записать фактический database_id.
3. Настроить доступ к демо, задать тестовый токен и webhook secret через защищённые настройки Workers. В репозиторий секреты не добавлять.
4. Применить миграции к новой базе, загрузить только `seeds/demo.sql`.
5. Выполнить `pnpm build` (dry run), затем развернуть основной `src/index.ts` отдельным Worker. Осознанно включить адрес workers.dev либо выделенный маршрут.
6. Выполнить проверки HTTPS, D1, сохранности данных после повторной публикации, Cron и лимитов.
7. Только после отдельного разрешения настроить webhook/кнопку меню **тестового** бота. Приложение само не вызывает setWebhook, setChatMenuButton или setMyCommands.
8. Проверить реальные тестовые аккаунты Telegram и доставку уведомлений. Старый Render и действующий бот сохранять до согласованного перехода.

## Проверенные бесплатные лимиты

Сверено 22 октября 2026 по официальной документации. Workers Free: 100 000 запросов/сутки и 10 мс CPU HTTP-запроса; 50 subrequests на вызов. D1 Free: 5 млн прочитанных и 100 000 записанных строк/сутки; 500 МБ на базу, 5 ГБ суммарно, 10 баз; Time Travel 7 дней. Индексы и триггеры тоже расходуют ресурсы. Cron обрабатывает максимум 5 доставок за тик. CPU/суточную нагрузку нужно измерить на развёрнутом экземпляре; локальные тесты не подтверждают укладывание в облачный CPU-бюджет.

Цель — нулевая обязательная стоимость в этих лимитах. Платные сервисы не подключались. Бесплатный тариф не означает SLA или гарантированную круглосуточную доступность.

Источники: [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/), [Telegram initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Резервирование и восстановление

Time Travel не заменяет независимую резервную копию. Для локальной проверки:

```sh
pnpm exec wrangler d1 export barbershop-37-demo --local --output demo-backup.sql
```

В облаке использовать `--remote` только с проверенным именем исходной базы. Хранить экспорт вне GitHub с ограниченным доступом; он может содержать персональные данные. Для восстановления создать отдельную пустую тестовую D1, импортировать SQL, проверить `foreign_key_check`, `quick_check`, количество услуг/мастеров/визитов, затем сценарии записи и авторизации. D1 не поддержала `integrity_check` в этой локальной проверке; использован разрешённый `quick_check`. Не импортировать поверх рабочей базы. Согласовать переключение только после проверки. Успех локального round-trip не является проверкой восстановления удалённой D1/Time Travel.

## Осталось перед коммерческой демонстрацией

Управление исключениями рабочего времени на отдельную дату, персональные QR-коды и полноценное подтверждение телефона ещё не завершены. Приём реальных контактов отключён намеренно; webhook в демо не сохраняет присланный номер. Требуются проверки всех кабинетов в Telegram, редактирование армянского носителем, живые уведомления/Cron, облачный backup/restore, политика хранения/экспорта/удаления данных и инструкции для передачи салону. Перед реальным запуском необходимы согласие владельца и юридическая проверка обработки данных в Армении. `APP_MODE != demo` блокируется сервером: это не скрытый переключатель для эксплуатации.

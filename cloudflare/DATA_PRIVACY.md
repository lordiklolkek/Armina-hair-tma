# Данные, конфиденциальность и прекращение обслуживания

Обновлено 23.10.2026. Технический регламент закрытой демоверсии. Коммерческий запуск и настоящие записи не разрешены. Это основа для согласования с салоном и юридической проверки в Армении, не утверждённая политика действующего салона. До запуска назначить ответственное лицо, опубликовать его контакты, цели и согласованные сроки хранения. Правовую оценку проводить по актуальным документам, в том числе [закону Армении о защите персональных данных в ARLIS](https://www.arlis.am/en/acts/117034/latest); наличие этого регламента не подтверждает соответствие закону.

## Что сохраняет текущая версия

- Telegram ID и язык пользователя; номер и время подтверждения — только после отдельного запроса и согласия Telegram.
- Профили сотрудников, их привязки Telegram, услуги, графики и отсутствие.
- Клиенты и история визитов со снимками названий, цены и времени; приватные заметки по паре мастер/клиент.
- Очередь служебных сообщений, состояния/попытки доставки и журнал административных действий.
- Временно: хеши одноразовых приглашений, запросы проверки контакта, ID обработанных событий и счётчики ограничений.

Подтверждённый номер хранится в users и clients. Для связи он показывается в доступных мастеру карточках визитов/клиентов и в уведомлении назначенному мастеру. Старому мастеру при передаче визита новое сообщение с номером не отправляется. Отправленное сообщение и скачанный экспорт создают дополнительные копии вне основной D1; очистка D1 не отзывает их автоматически.

BOT_TOKEN, списки разрешённых аккаунтов/администраторов и webhook-ключи находятся в Cloudflare Secrets. Они не являются бизнес-выгрузкой. initData проверяется сервером; полные события, номера, токены и тексты сообщений не должны попадать в технические логи. Диагностика владельца не показывает содержимое очереди и ID получателей.

## Кто получает доступ

Администратор (OWNER_IDS или ADMIN_IDS) управляет салоном и видит все данные, включая экспорт. Уполномоченный администратор может работать без профиля мастера. Мастер получает только свои визиты, клиентов и заметки; чужой профиль недоступен. Клиент видит собственные визиты. Ссылка запуска и приглашение сами по себе не дают административного доступа. В демо дополнительным ограничением служит DEMO_USER_IDS.

Новому человеку права выдаются только по согласованию. Отзыв привязки/архивирование проверяется при отправке очереди: отозванному сотруднику новые данные не отправляются. Нельзя обещать удаление уже полученных им сообщений или сделанных им копий.

## Бизнес-экспорт из панели

«Управление → Экспорт данных». Раздел доступен администратору. Выберите набор, нажмите «Подготовить первую часть», затем «Скачать JSON». При наличии продолжения скачайте текущую часть и подготовьте следующую. Повторите для всех нужных разделов. Каждая часть содержит до 250 строк, dataset/schema_version/part/after/through/next_cursor и время подготовки. Пустой раздел тоже выдаёт корректную последнюю часть. Строки не обрезаются молча.

Доступны клиенты, визиты/история, заметки, сотрудники, услуги/цены, услуги сотрудников, недельные графики, исключения дат, отсутствие, аккаунты Telegram и настройки. Перечень полей задан явно. Токены, webhook-ключи, одноразовые приглашения, контактные запросы, очередь доставки, служебное состояние и ключи идемпотентности не включаются.

Это выгрузка бизнес-данных для передачи/анализа, не полный SQL backup и не готовый автоматический импорт в новую установку. Граница страниц фиксируется по ключу набора; отдельные части не являются единым транзакционным снимком. На время выгрузки согласуйте окно без изменений; при изменениях повторите выгрузку. Для точного восстановления используйте полный D1 SQL export и проверку отдельной копии по OPERATIONS.md.

Файл содержит личные данные. Сохраняйте его в защищённой папке/зашифрованном хранилище; не загружайте в GitHub, публичные ссылки или чат поддержки. Передавайте только согласованному получателю по защищённому каналу. После передачи подтвердите получение и согласуйте удаление временных копий. Демоверсия не шифрует скачанный JSON отдельным паролем и не удаляет копии на устройстве.

## Фактическая очистка и нерешённые сроки

Текущий код удаляет ID обработанных Telegram-событий старше 7 дней, счётчики ограничений старше часа, приглашения через сутки после истечения и запросы контакта через сутки после истечения. Очистка выполняется фоновым циклом, а не точно в указанную секунду.

Для users/clients, визитов, заметок, audit_log и отправленной/ошибочной очереди автоматический срок удаления пока не утверждён и не реализован. Это незавершённая задача перед реальной эксплуатацией. Отправленный текст уведомления мастеру может содержать номер: учесть и эту копию при выборе сроков. Не придумывать сроки хранения от имени салона и не объявлять их юридически обязательными без проверки.

## Запрос копии, исправления или удаления

1. Получить запрос от самого человека по проверенному каналу; не считать знание чужого номера подтверждением личности. В закрытом тесте запрос передаётся организатору теста. Для production нужен опубликованный контакт ответственного.
2. Уточнить объём: исправление номера, отзыв связи, копия данных или удаление/обезличивание. Не выдавать человеку данные других клиентов и приватные заметки сотрудников автоматически; объём предоставления согласовать с ответственным и юристом.
3. Найти связи в users/clients, визитах и created_by, привязках мастеров, заметках, очереди/текстах, audit_log, приглашениях и контактных запросах; отдельно учесть SQL backup, скачанные JSON и Telegram-сообщения. Минимальные ID событий не содержат связи с человеком и очищаются по общему сроку.
4. Подготовить конкретный план с сохранением целостности и нужной бизнес-истории. Отмена визита не удаляет профиль; архивирование сотрудника не заменяет удаление личных данных. Прямая очистка users может нарушить внешние ключи. Нельзя стирать историю или переписывать сотрудника в другого человека ради удаления.
5. Проверить план на отдельной тестовой копии. Для необратимого применения получить отдельное разрешение пользователя/уполномоченного ответственного. До этого основную D1 и резервные копии не удалять.
6. После согласованного исполнения проверить внешние ключи, доступы, очередь, копии и отсутствие повторного раскрытия при восстановлении. Зафиксировать результат без номера и токенов. Автоматическая кнопка полного удаления/обезличивания в текущей версии ещё не реализована.

## Прекращение обслуживания и передача

1. Согласовать дату, уполномоченного получателя, перечень данных, судьбу действующих визитов/уведомлений и время проверки. Не прекращать обслуживание внезапно из-за завершения демо.
2. Сохранить подтверждённый commit, версию Worker, схему миграций, полный D1 SQL export и бизнес-выгрузки. Хранить вне публичного репозитория. Зафиксировать контрольные суммы и проверить восстановление в отдельной непривязанной базе.
3. Подготовить новую установку/аккаунт получателя с минимальными правами. Секреты передавать отдельным согласованным защищённым способом или вводить самим владельцем. Передача JSON не требует включать BOT_TOKEN в файл. Не создавать оплачиваемые ресурсы без разрешения.
4. Получатель проверяет роли, базу, webhook, меню, уведомления, контакты и собственный вход в настоящем Telegram. Старый Render/Worker сохранять до успешной проверки. Не сбрасывать ожидающие Telegram-события и не включать автоматическую регистрацию Render.
5. Переключение действующего бота и реальных записей выполняется только после отдельного разрешения. Сохранить проверенный способ возврата. Не считать успешный deploy доказательством передачи.
6. После подтверждения приёмки отдельно согласовать отзыв прежних доступов, ротацию ключей, отключение старого сервиса и удаление временных/резервных копий с учётом утверждённых сроков. Не применять эти действия автоматически по истечении таймера.

Сейчас никакого прекращения обслуживания, передачи данных третьему лицу или необратимого удаления не выполнялось. Для коммерческой готовности остаются утверждённые сроки/ответственное лицо, проверенный инструмент удаления/обезличивания, автоматизация защищённых резервных копий и полный сценарий передачи на согласованных данных.


### Получение экспорта в Telegram

Обычная ссылка на Blob в некоторых Telegram WebView открывает JSON текстом. После подготовки части есть отдельная кнопка «Получить файл в чате»: подписанный администратор явно просит отправить серверный JSON-документ лично себе. Получатель берётся только из проверенной подписи, произвольные chat_id/содержимое запрещены. До 3 попыток в минуту на аккаунт; автоматического повтора нет. После сетевой ошибки сначала проверить чат, чтобы не создавать дубликат. Каждая часть до 250 строк; продолжение доступно после принятия документа Telegram. Это не подтверждение сохранения пользователем. Копия с личными данными выбранного раздела остаётся в Telegram, о чём интерфейс предупреждает перед нажатием. Удаление из D1 не удаляет сохранённые/отправленные копии. Для безопасного теста выбирать «Услуги и цены».

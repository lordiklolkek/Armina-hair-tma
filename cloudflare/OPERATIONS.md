# Работа с демоверсией 37

## Владельцу

Откройте приложение через тестовый Telegram-бот под разрешённым аккаунтом. Раздел «Управление» появляется только после серверной проверки роли.

**Новый мастер:** «Управление → Выберите мастера → Добавить мастера». Достаточно имени. Затем откройте «Кабинет мастера», назначьте услуги, длительность и рабочие часы. После настройки включите онлайн-запись в редакторе профиля. Telegram на этом шаге не обязателен. Количество сотрудников не зафиксировано в коде.

**Привязка Telegram:** в профиле нажмите «Привязать Telegram». Передайте одноразовую ссылку только нужному тестировщику. Она действует 15 минут; пользователь должен открыть её и отправить /start внутри личного чата тестового бота. Участник должен быть включён в список разрешённых демоаккаунтов. Сам клиент не может назначить себе роль. Для замены аккаунта сначала отзовите прежний доступ, затем создайте новое приглашение.

**Увольнение/архив:** сначала просмотрите количество будущих записей. Архивирование требует подтверждения сохранения визитов; профиль и история остаются, новые записи закрываются, привязка сотрудника отзывается. Переносите или отменяйте затронутые визиты из списка записей. Массовая отмена одним действием пока не реализована. Для нового человека создавайте новый профиль: не переименовывайте уволенного сотрудника в нового ради переноса истории.

**Цены:** «Управление → Услуги и цены». Для фиксированной цены укажите одинаковые минимальную и максимальную суммы. Для диапазона — обе границы. Клиент увидит диапазон и пояснение. Изменение прайса не переписывает цену уже созданного визита. Временные значения длительности из демо необходимо согласовать до эксплуатации.

**Настройки:** доступны название, адрес, ссылка HTTPS на логотип, горизонт записи и минимальное время до визита. Без логотипа используется временное типографическое «37».

## Мастеру

После привязки откройте «Кабинет мастера». Здесь доступны только ваши записи, клиенты, заметки, график и индивидуальная длительность. Владелец имеет доступ ко всем профилям.

В графике можно задать два рабочих интервала в день; промежуток между ними будет перерывом. Оставьте оба времени пустыми для выходного. «Отсутствие» позволяет закрыть отпуск или иной интервал; личная причина клиентам не раскрывается. Если изменение конфликтует с уже созданной записью, сервер отклонит его целиком. Сначала согласуйте перенос/отмену визита.

«Рабочий график → График на отдельную дату» заменяет обычные часы только на выбранный день. Можно задать до восьми интервалов или нажать «Выходной». Сохранённые даты перечислены ниже. «Вернуть недельный график» убирает исключение, если обычные часы вмещают существующие визиты. Одновременное редактирование из двух окон требует обновить устаревшее окно. Время окончания 00:00 означает конец выбранного дня.

«Ссылки и QR-код» в кабинете мастера показывает его персональную ссылку; владелец также выбирает общий адрес или другого активного мастера. Ссылку можно скопировать, QR — сохранить в PNG. Пока прямой адрес Mini App не настроен, интерфейс явно обозначает браузерный предпросмотр. Для Telegram разработчик задаёт проверенный MINI_APP_URL, например https://t.me/YourBot/demo37; параметр startapp выбирает мастера, но не даёт роли и не отменяет проверку подписи.

В «Мои услуги» меняется только ваша длительность; общие цены изменяет владелец. Вручную добавленный тестовый визит сразу занимает время и не требует Telegram-аккаунта клиента. В демо используются только вымышленные имена и контакты; поля реальных данных не открыты.

В деталях записи можно сохранить итоговую согласованную цену и выделить дополнительные минуты без изменения цены. Для конфликтующего продления потребуется выбрать другой интервал. «Завершён» и «Неявка» доступны только после начала визита. Приватные заметки хранятся отдельно по мастеру и клиенту; другой мастер их не получает.

## Сценарий закрытого показа

1. Показать заметное предупреждение о неофициальном демо и вымышленных данных.
2. Переключить язык HY/RU, показать каталог и диапазоны цен.
3. Выбрать услугу, мастера, дату и время; создать тестовую запись.
4. Открыть «Мои записи», выполнить перенос и отмену.
5. Добавить мастера с одним именем; назначить услуги и часы без редактирования кода.
6. Показать индивидуальную длительность, перерыв и отпуск.
7. Попробовать создать конфликт — сервер должен отказать, сохранив исходную запись.
8. Показать архив/восстановление и сохранность истории.
9. Честно обозначить, какие проверки Telegram и облачной инфраструктуры ещё не выполнены. Не принимать реальные заказы до согласования с владельцем салона.

## Разработчику: обновление и откат

Продолжать в ветке `development/37-barbershop`, сначала читать корневой PROJECT_PROGRESS.md. Проверки: `pnpm check`, `pnpm test`, `pnpm build`; публикация: `pnpm run deploy` (готовит QR asset перед Wrangler; явное run отличает скрипт от встроенной команды pnpm deploy). Исходный backend: `python -m pytest -q`, `node --test tests/frontend.test.cjs`. Новые изменения сначала проверять на отдельной тестовой D1.

Перед облачной миграцией экспортировать исходную D1, проверить копию на отдельной базе и сохранить идентификатор предыдущей версии Worker. Применять только новые миграции; после выпуска их нельзя переписывать. При неудачном обновлении откатить Worker только к схеме, с которой он совместим. Данные при необходимости восстанавливать в новую D1 и переключать привязку после проверки; не затирать рабочую базу импортом. Render и действующий бот не переключаются автоматически.

Первоначально выполнен **локальный** SQL export/import в отдельную D1: восстановлены 8 услуг, 4 тестовых профиля, 1 тестовая запись и 5 триггеров. `PRAGMA quick_check` вернул `ok`, `foreign_key_check` — пустой результат. Независимые копии хранить вне публичного GitHub. Для рабочей базы нужны согласованные сроки хранения, шифрование и ограничение доступа.

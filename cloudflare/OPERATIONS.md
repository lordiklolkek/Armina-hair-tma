## Владельцу

Административную работу может вести уполномоченный человек вместо владельца салона: разработчик задаёт его Telegram ID в закрытом ADMIN_IDS и, для демо, DEMO_USER_IDS. Профиль мастера ему не нужен. Новые права выдаются только после согласования; через ссылку запуска или клиентский запрос получить их нельзя. Мастера ограничены своими визитами, клиентами и заметками на сервере; администратор видит все профили.

Переход @ArminaHair_Bot на Cloudflare выполнен с явного разрешения пользователя. Render сохранён, обновлён до d1bd09d и больше не регистрирует webhook при старте; Auto-Deploy выключен. [Результат, план возврата и обязательные живые проверки](TELEGRAM_MIGRATION.md). Пользователь разрешил живой тест номера; флаг контакта включён, передача требует отдельного согласия внутри Telegram. Результат живого подтверждения фиксировать отдельно.

**Календарь:** «Управление → Календарь». Укажите обе даты включительно (до 31 дня), при необходимости выберите мастера и статус. Визиты сгруппированы по дням по времени Армении. «Загрузить ещё» открывает следующие 100 визитов; прежний общий предел 200 к этому экрану не применяется. Архивный мастер остаётся в фильтре для просмотра истории. После изменения статуса календарь обновляется с выбранными фильтрами. У мастера тот же календарь ограничен собственными визитами на сервере.

**Контакт клиента:** телефон доступен в карточке визита и в списке клиентов своего мастера/администратора. При наличии корректного номера можно нажать на него для звонка. В уведомлении назначенному мастеру показывается подтверждённый контакт; технического номера визита в тексте больше нет. После передачи визита прежнему мастеру новое сообщение с номером не отправляется. Уже отправленные копии Telegram сохраняются.

**Экспорт:** «Управление → Экспорт данных», выберите набор, подготовьте и скачайте все части. Каждый файл содержит не более 250 строк. Файлы содержат личные данные; доступ даётся только администратору, не мастеру/обычному клиенту. Подробности, ограничения согласованного снимка, запросы удаления и передача обслуживания: [DATA_PRIVACY.md](DATA_PRIVACY.md).

**Уведомления:** прямой путь «Управление → Уведомления». Для теста нажмите «Проверить уведомления → Отправить мне тестовое сообщение». Раздел также сохранён внизу настроек. Пользователь подтвердил получение теста после миграции; уведомления о создании, переносе, отмене и напоминания собственным аккаунтом также прошли описанные в PROJECT_PROGRESS.md проверки.

**Доступ клиента:** «Управление → Клиенты». Блокировка запрещает новые онлайн-записи, сохраняя существующие визиты и возможность клиента их отменить. В карточке доступны счётчики завершённых визитов и неявок. Изменение требует подтверждения внутри приложения; конфликт с параллельным редактированием требует обновления списка. Ручной клиент без Telegram не имеет переключателя доступа. Клиенты загружаются страницами по 100.

**Текущий бот:** webhook и меню @ArminaHair_Bot уже направлены на Cloudflare. Это позволяет принимать /start и приглашения; ответ /start, подтверждение номера и приглашение мастера проверены пользователем на собственном аккаунте. Отдельные аккаунты клиента и двух мастеров ещё нужны для полного живого теста. Старые callback-кнопки пересылаются в сохранённый Render с отдельным ключом. Имя/username планируется изменить позже: затем обновить BOT_USERNAME, MINI_APP_URL (если задан), приглашения и QR. Секреты хранятся в Cloudflare, в исходники их не добавлять.

Откройте приложение через тестовый Telegram-бот под разрешённым аккаунтом. Раздел «Управление» появляется только после серверной проверки роли.

**Новый мастер:** «Управление → Выберите мастера → Добавить мастера». После имени открывается пошаговая настройка: 1) «Выбрать услуги и длительность»: отметьте нужные услуги и сохраните их; 2) «Задать рабочие часы»: раскройте недельный график, заполните интервалы и сохраните; 3) вернитесь назад и нажмите «Показывать при записи». Для уже добавленного профиля есть кнопка «Настроить запись». До назначения услуг/часов включение недоступно. Статус «Не показывается клиентам» объясняет недостающие шаги; «Активен» сам по себе не означает участие в онлайн-записи. Клиент видит мастера только для назначенной ему услуги; свободное время зависит от графика. Каталог обновляется при каждом начале новой записи. Услуги и графики автоматически не копируются из другого профиля. Telegram на этом шаге не обязателен. Количество сотрудников не зафиксировано в коде.

**Привязка Telegram:** в профиле нажмите «Привязать Telegram». Передайте одноразовую ссылку только нужному тестировщику. Она действует 15 минут; пользователь должен открыть её и отправить /start внутри личного чата тестового бота. Участник должен быть включён в список разрешённых демоаккаунтов. Сам клиент не может назначить себе роль. Для замены аккаунта сначала отзовите прежний доступ, затем создайте новое приглашение.

**Увольнение/архив:** нажмите «Архивировать» в профиле. Откроется список назначенных незавершённых визитов, включая уже начавшиеся. Можно отключить новые записи, сохранив визиты, перенести отдельные визиты или явно подтвердить отмену всех назначенных. История не удаляется, привязка сотрудника отзывается. Для ручных клиентов без Telegram самостоятельно сообщите об изменении. Если после просмотра список изменился (даже при том же количестве), сервер потребует обновить его перед отменой. Такой же выбор предусмотрен при отключении флага «Активен». Для нового человека создавайте новый профиль: не переименовывайте уволенного сотрудника в нового ради переноса истории.

**Передача визита:** «Календарь → Перенести → Мастер для переноса». Выберите активного мастера с нужной услугой, проверьте дату/слот и подтвердите. Перенос к другому мастеру разрешён только владельцу. Согласованные цена, название и длительность сохраняются; занятое время или неподходящая услуга отклоняются без потери исходной записи. Клиенту и связанным действующим мастерам создаются задания уведомлений. При этом отправка настоящих уведомлений о визитах ещё требует отдельной интеграционной проверки.

**Цены:** «Управление → Услуги и цены». Для фиксированной цены укажите одинаковые минимальную и максимальную суммы. Для диапазона — обе границы. Клиент увидит диапазон и пояснение. Изменение прайса не переписывает цену уже созданного визита. Временные значения длительности из демо необходимо согласовать до эксплуатации.

Здесь также редактируются описания HY/RU и числовой порядок в каталоге (меньшее значение выше). Изменение цены сохраняет заполненные описания и порядок. Язык авторизованного пользователя хранится на сервере и восстанавливается при следующем входе.

**Уведомления:** новые сообщения различают создание, отмену и перенос; показывают услугу, мастера, время Армении, цену/диапазон и выбранный язык получателя (по умолчанию HY). При переносе указаны прежние время/мастер. Устаревшие задания помечаются SUPERSEDED, после отзыва Telegram сотрудника задания ему не доставляются. Сообщения отправляются обычным текстом без HTML-разметки. Не обещается строго однократная доставка при сетевой неопределённости. Очередь содержит снимок события; сообщение использует сохранённый язык на момент попытки отправки. Повторы и количество отправок за один Cron остаются ограниченными.

**Проверка доставки:** «Управление → Настройки → Уведомления → Проверить уведомления». После явного нажатия «Отправить мне тестовое сообщение» задание адресуется только вошедшему владельцу. Настоящий визит не создаётся; повторные нажатия ограничены. Нажмите «Обновить», чтобы увидеть состояние. Само состояние «Отправлено» означает успешный ответ Telegram, а получение сообщения нужно проверить в личном чате.

В этом разделе есть фильтр состояния, страницы по 100 сообщений и понятные причины ошибок без отображения текста сообщений и Telegram ID получателей. После устранения временного сбоя можно явно подтвердить «Повторить отправку». Заменённые сообщения и сообщения отозванному сотруднику повторно отправить нельзя. Проверки версии визита и доступа распространяются и на текстовую очередь предыдущей версии. При неопределённом сетевом ответе повтор может привести к дубликату — интерфейс предупреждает об этом. Автоматическое отдельное оповещение владельца обо всех критических технических ошибках пока не реализовано.

**Настройки:** доступны название, адрес, ссылка HTTPS на логотип, горизонт записи и минимальное время до визита. Без логотипа используется временное типографическое «37».

## Мастеру

После привязки откройте «Кабинет мастера». Здесь доступны только ваши записи, клиенты, заметки, график и индивидуальная длительность. Владелец имеет доступ ко всем профилям.

В графике можно задать два рабочих интервала в день; промежуток между ними будет перерывом. Оставьте оба времени пустыми для выходного. «Отсутствие» позволяет закрыть отпуск или иной интервал; личная причина клиентам не раскрывается. Если изменение конфликтует с уже созданной записью, сервер отклонит его целиком. Сначала согласуйте перенос/отмену визита.

«Рабочий график → График на отдельную дату» заменяет обычные часы только на выбранный день. Можно задать до восьми интервалов или нажать «Выходной». Сохранённые даты перечислены ниже. «Вернуть недельный график» убирает исключение, если обычные часы вмещают существующие визиты. Одновременное редактирование из двух окон требует обновить устаревшее окно. Время окончания 00:00 означает конец выбранного дня.

«Ссылки и QR-код» в кабинете мастера показывает его персональную ссылку; владелец также выбирает общий адрес или другого активного мастера. Ссылку можно скопировать, QR — сохранить в PNG. Пока прямой адрес Mini App не настроен, интерфейс явно обозначает браузерный предпросмотр. Для Telegram разработчик задаёт проверенный MINI_APP_URL, например https://t.me/YourBot/demo37; параметр startapp выбирает мастера, но не даёт роли и не отменяет проверку подписи.

В «Мои услуги» меняется только ваша длительность; общие цены изменяет владелец. Вручную добавленный тестовый визит сразу занимает время и не требует Telegram-аккаунта клиента. В демо используются только вымышленные имена и контакты; поля реальных данных не открыты.

В деталях записи можно сохранить итоговую согласованную цену и выделить дополнительные минуты без изменения цены. Для конфликтующего продления потребуется выбрать другой интервал. «Завершён» и «Неявка» доступны только после начала визита. Приватные заметки хранятся отдельно по мастеру и клиенту; другой мастер их не получает.

## Сценарий закрытого показа

1. Показать заметное предупреждение о неофициальном демо и вымышленных данных.
2. Переключить язык HY/RU, показать каталог и диапазоны цен.
3. Выбрать услугу, мастера, дату и время; создать тестовую запись.
4. Открыть «Мои записи», выполнить перенос и отмену.
5. Добавить мастера с одним именем; назначить услуги и часы без редактирования кода.
6. Показать индивидуальную длительность, перерыв и отпуск.
7. Попробовать создать конфликт — сервер должен отказать, сохранив исходную запись.
8. Показать архив/восстановление и сохранность истории.
9. Честно обозначить, какие проверки Telegram и облачной инфраструктуры ещё не выполнены. Не принимать реальные заказы до согласования с владельцем салона.

## Разработчику: обновление и откат

Продолжать в ветке `development/37-barbershop`, сначала читать корневой PROJECT_PROGRESS.md. Проверки: `pnpm check`, `pnpm test`, `pnpm build`; публикация: `pnpm run deploy` (готовит QR asset перед Wrangler; явное run отличает скрипт от встроенной команды pnpm deploy). Перед облачной миграцией экспортировать исходную D1, проверить копию на отдельной базе и сохранить идентификатор предыдущей версии Worker. Применять только новые миграции; после выпуска их нельзя переписывать. При неудачном обновлении откатить Worker только к схеме, с которой он совместим. Данные при необходимости восстанавливать в новую D1 и переключать привязку после проверки; не затирать рабочую базу импортом. Render и действующий бот не переключаются автоматически.

### Скорость доставки после живых проверок

Создание, перенос, отмена и тест самому себе запускают отправку сразу после сохранения. /start, приглашение и ответ на контакт — после webhook. Результат HTTP не зависит от доступности Telegram: ошибка сохраняется для повтора. Отправка ограничена двумя подходящими заданиями; третий участник передачи, массовая операция и временные сбои могут ждать фоновый цикл. Cron настроен раз в минуту, до пяти заданий за запуск. При изменении расписания облаку требуется время распространения; до подтверждения факта не обещать пользователю мгновенную доставку.


### Получение экспорта в Telegram

Обычная ссылка на Blob в некоторых Telegram WebView открывает JSON текстом. После подготовки части есть отдельная кнопка «Получить файл в чате»: подписанный администратор явно просит отправить серверный JSON-документ лично себе. Получатель берётся только из проверенной подписи, произвольные chat_id/содержимое запрещены. До 3 попыток в минуту на аккаунт; автоматического повтора нет. После сетевой ошибки сначала проверить чат, чтобы не создавать дубликат. Каждая часть до 250 строк; продолжение доступно после принятия документа Telegram. Это не подтверждение сохранения пользователем. Копия с личными данными выбранного раздела остаётся в Telegram, о чём интерфейс предупреждает перед нажатием. Удаление из D1 не удаляет сохранённые/отправленные копии. Для безопасного теста выбирать «Услуги и цены».

### Язык сообщений и технические предупреждения

Mini App сохраняет выбор HY/RU. Новые ответы /start, приглашения, подтверждение номера, тест доставки, уведомления о визитах и напоминания отправляются на армянском независимо от этого выбора. Кнопка в сообщениях и меню бота — «Գրանցվել». Уже отправленные сообщения не редактируются. Исторические текстовые задания без снимка события поддерживаются в прежнем виде; действующая очередь при проверке не содержала ожидающих заданий.

OPS_ALERTS_ENABLED=true включает проверку очереди в минутном цикле. Если есть технические отказы за последние сутки, просрочка готового к отправке задания более десяти минут или проблема подключения Telegram/накопление не менее десяти входящих обновлений, создаётся общее предупреждение. Получатель — первый разрешённый демоадминистратор ADMIN_IDS, иначе OWNER_IDS. Уведомление не содержит клиентов, телефонов, текстов заданий или секретов. Не более одного за шестичасовое окно. Отозванные/устаревшие сообщения и сами технические предупреждения не порождают новые предупреждения. Раздел «Уведомления» позволяет проверить причины и допустимый повтор.

Это внутренний контроль: при полной недоступности Telegram предупреждение дождётся восстановления доставки; при отказе D1/Worker/Cron он не заменяет внешний мониторинг. /health проверяет обращение к D1; безопасные api_error логи и метрики доступны в Cloudflare. Внешний бесплатный монитор и подтверждение CPU на настоящих приватных сценариях ещё не настроены/не завершены.

### Бесплатное восстановление и независимые копии

В D1 Free доступно автоматическое восстановление Time Travel в пределах семи дней: [официальные ограничения](https://developers.cloudflare.com/d1/platform/limits/). 24 октября чтение time-travel info для действующей базы успешно вернуло bookmark. Это проверка доступности истории, а не повторный restore; успешное восстановление непустой истории ранее выполнено на отдельной тестовой базе и описано выше. Основную базу не откатывали.

Независимая копия требует отдельного защищённого хранения вне Cloudflare. Практический регламент: перед миграциями и ежедневно при реальных записях остановить изменения на время SQL export, выгрузить D1 в закрытую папку на зашифрованном носителе, зашифровать переносимую копию проверенным инструментом, сохранить контрольную сумму и копию вне аккаунта Cloudflare; ключ восстановления держать отдельно. SQL с контактами нельзя помещать в публичный GitHub, CI-логи или общие outputs. Раз в месяц восстановить копию только в новую непривязанную D1 и проверить quick_check, foreign_key_check, таблицы и триггеры. Рабочую базу не заменять импортом. Ответственный, защищённое место и автоматический запуск такого процесса ещё требуют выбора; независимая автоматизация не объявляется готовой.

24 октября отдельно создана полная зашифрованная локальная копия текущей D1 вне репозитория: work/private-backups/37-2026-10-24.sql.dpapi. Папка закрыта правами Windows (текущий пользователь + SYSTEM). DPAPI CurrentUser, расшифровка с совпадением SHA256 и приватный Restore-Backup.ps1 проверены; временный SQL удалён. Содержимое не публикуется. Восстановление в облачную D1 этой новой копии не выполнялось. Расшифровать её можно с ключами того же Windows-профиля; копия не покрывает потерю этого профиля/компьютера. Это независимость от Cloudflare, но не отдельный носитель с переносимым ключом и не ежедневная автоматизация. Подробности в приватном RECOVERY.md рядом с файлом.

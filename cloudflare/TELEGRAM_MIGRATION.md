## Перед переключением

1. Сохранить исходную Render SQLite и проверить восстановление отдельной копии. Не путать её с уже проверенным резервированием новой Cloudflare D1. Старые API показывают каталог/расписания и максимум 250 визитов, но не полный файл/все поля/пользователей. Их выгрузка не является полной резервной копией.
2. Render Dashboard подтверждён: Free, service `srv-db5nhlvavr4c739e2fm0`, ветка main, рабочий commit `44286301f71cfd70e35500f21a1798b0ba448710`. Shell/SSH недоступны на Free; платное повышение не выполнять. Пока источник не сохранён, не выполнять redeploy/restart и не менять рабочую ветку сервиса. Это остаётся конкретной незавершённой задачей.
3. После сохранения исходных данных применить к Render проверенное изменение `main.py`: `TELEGRAM_AUTO_CONFIGURE=false` по умолчанию и в render.yaml. Проверить после перезапуска, что `getWebhookInfo` не изменился. Просто добавление переменной к старому commit недостаточно: он её не читает. Исходные данные, меню и старый сервис пока сохраняются.
4. Задать новый WEBHOOK_SECRET через Cloudflare Secrets. Секрет не публиковать; допустимы 32–256 символов A–Z/a–z/0–9/_/-. BOT_TOKEN, OWNER_IDS, DEMO_USER_IDS уже заданы, повторно их не запрашивать. APP_URL должен быть точным HTTPS origin новой версии. Нужен проверенный план возврата, включая прежний webhook secret; getWebhookInfo не возвращает этот секрет.
5. Применить новые D1 миграции, выполнить полный набор тестов и production build, затем deploy. Сохранить предыдущую версию Worker и D1 export вне GitHub. Проверить health/config, отказ без initData, отказ webhook без/с неверным секретом, принятие подписанного пустого технического update без сообщения и отсутствие задания отправки. Не имитировать реальное событие от имени человека.
6. Проверить исходящие Bot API getMe/getWebhookInfo. Фоновый монитор и раздел «Настройки → Уведомления → Проверить подключение бота» используют только эти методы, не меняют webhook/меню и не отправляют сообщений. Сведения лежат в integration_status без токена/секрета/текста ошибки Telegram.
7. Старые callback-кнопки модерации требуют отдельного совместимого маршрута или завершения старых заявок до переключения. Новая версия не должна терять старые события. Согласовать допустимые тестовые аккаунты; демо остаётся закрытым списком и не обслуживает настоящих клиентов.

## Подтверждение и переключение

После пунктов выше показать пользователю точные старый/новый URL, состояние базы, результаты тестов, ограничения демо и план возврата. Запросить одно подтверждение именно на замену webhook. Не использовать общее «продолжай» вместо этого подтверждения. Не применять drop_pending_updates=true.

После подтверждения: setWebhook на `https://barbershop-37-demo.barbershop-37.workers.dev/telegram/webhook` с новым secret_token и осознанным списком allowed_updates. Затем getWebhookInfo должен вернуть точный URL, а ожидающие события должны обрабатываться без растущей ошибки. Публичную кнопку меню переключать только в согласованном объёме. Старый Render не удалять и не отключать.

## Обязательные живые проверки

- Владелец/уполномоченный администратор открывает приложение, обычный клиент не видит управление. ADMIN_IDS задаётся как закрытый список в серверной конфигурации; фактическое предоставление доступа новому человеку согласуется отдельно. Профиль барбера администратору не нужен.
- Владелец нажимает тест отправки самому себе; дождаться «Отправлено» и подтвердить получение в Telegram. Реальные сообщения другим людям без разрешения не отправлять.
- Создать одноразовое приглашение, принять его нужным разрешённым аккаунтом. Проверить 15 минут, повторное использование, второе приглашение, отзыв/архив и одновременное принятие. Неверная ссылка теперь отвечает понятным сообщением и завершается без бесконечных повторов Telegram.
- Два мастера проверяют изоляцию записей, клиентов и приватных заметок. Администратор видит оба профиля. Локальные автоматические проверки пройдены; это не заменяет живой Telegram.
- Включить CONTACT_VERIFICATION_ENABLED только для согласованного теста контакта. Приложение сначала создаёт десятиминутный запрос, затем вызывает официальный requestContact. Номер принимает только секретом защищённый webhook с совпадением from.id = chat.id = contact.user_id, свежей датой, личным чатом и без пересылки. JavaScript не может заявить «номер подтверждён». Повтор/просрочка не меняют номер. Перед согласием пользователь видит, что номер сохранится в Cloudflare и станет доступен уполномоченным сотрудникам.
- Проверить создать/перенести/отменить визит, локализованные уведомления и оба напоминания, конфликтующий слот, отсутствие дубля при повторном нажатии. Тестовые сообщения маркируются демо; реальные записи остаются отключены.
- Только после проверки запуска через бота включить TELEGRAM_LINKS_ENABLED. Ссылки `?start=booking` и `?start=barber_<id>` не требуют Main Mini App в BotFather: /start выдаёт web_app-кнопку с нужным мастером. Длинный ID безопасно оставляет браузерную ссылку. Существующие прямые Mini App ссылки поддерживаются отдельно. Проверить реальные QR камерой и входом из Telegram.

Только после всех основных живых сценариев продолжать финальную проверку нагрузки/CPU и дизайн. Коммерческий запуск, настоящие данные салона и политика хранения требуют отдельного завершения; переключение webhook само по себе не включает production.

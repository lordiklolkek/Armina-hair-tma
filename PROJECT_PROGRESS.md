## Исходный аудит и решения

В старом проекте отсутствовали роли мастера, диапазоны и снимки цен, индивидуальная длительность, подтверждение контакта, идемпотентность, лимиты, очередь повторных уведомлений и HY/RU. Старый startup меняет публичные настройки бота; SQLite хранится локально. Исправления новой платформы выполняются отдельно, а не выкатываются поверх Render.

Новый проект использует D1 batch + SQL-триггеры; BEGIN IMMEDIATE из Python не переносится механически. Все неизвестные имена/длительности/часы хранятся в изменяемых демоданных. Не заменять реального сотрудника переименованием старого профиля.

## Как продолжать

Прочитать этот файл, cloudflare/README.md и cloudflare/OPERATIONS.md, сверить git status и remote ветку. Не создавать новый проект. Запуск: из cloudflare pnpm install --frozen-lockfile, pnpm check, pnpm test, pnpm db:local, pnpm seed:local (только первоначально), pnpm dev. Локальный UI fixture и ограничения описаны в README; его нельзя развёртывать в облако. График/QR, календарь/модерация, уведомления HY/RU и сценарии увольнения/передачи сохранены и размещены; вход владельца проверен в настоящем Telegram. Дизайн обсуждать в конце, как попросил пользователь. Для публикации использовать pnpm run deploy, чтобы сначала готовились QR assets. При Wrangler-командах использовать XDG_CONFIG_HOME=C:/Users/Рубен/Documents/Codex/2026-10-22/new-chat/work/cloudflare-auth и WRANGLER_LOG_PATH внутри той же папки, NODE_USE_SYSTEM_CA=1, WRANGLER_SEND_METRICS=false. Если вход истёк, повторить официальный OAuth, предпочтительно device flow; не извлекать браузерные cookies. Секреты и разрешённые ID уже заданы в Cloudflare — не запрашивать их заново, не читать значения и не добавлять в публичный конфиг.

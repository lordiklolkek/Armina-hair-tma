## Реализовано в cloudflare/

- SQL-схема: пользователи, мастера, услуги, индивидуальная длительность, графики, отсутствие, клиенты, записи, приватные заметки, приглашения, outbox, ограничения запросов и аудит.
- Проверка HMAC Telegram initData, срок 1 час; разрешённые тестовые ID, CLIENT/BARBER/OWNER. Владелец может одновременно быть мастером.
- Добавление мастера с одним именем, редактирование/фото, назначение услуг, отключение/архив/восстановление, отзыв Telegram и одноразовое приглашение на 15 минут.
- Архив не удаляет историю и требует подтверждения сохранения будущих записей.
- Общий прайс владельца, фиксированные цены/диапазоны, индивидуальные длительности. Цена/название/длительность визита сохраняются снимками.
- Онлайн- и ручная тестовая запись, любой мастер, перенос/отмена, завершение/неявка, итоговая цена, дополнительное время без изменения цены.
- Полные интервалы защищены SQLite-триггерами внутри D1; создание записи/уведомлений/аудита выполняется атомарной batch. Защита идемпотентности и optimistic version при изменении.
- Разделённый рабочий день, перерывы/отпуск, откат конфликтующего изменения графика или отсутствия.
- Лимиты клиента 1/2 будущих онлайн-визита по подтверждённой истории; ручные записи исключены из этого лимита.
- Приватные заметки в контексте мастера и клиента.
- Outbox, аренда задания при параллельном Cron, 24ч/2ч напоминания, повторы с backoff, предел 5 попыток, обработка 403/429 и исчерпанной аренды.
- Тёмный мобильный интерфейс 37, HY по умолчанию, RU, клиентский сценарий, кабинеты мастера/владельца.

## Исходный аудит и решения

В старом проекте отсутствовали роли мастера, диапазоны и снимки цен, индивидуальная длительность, подтверждение контакта, идемпотентность, лимиты, очередь повторных уведомлений и HY/RU. Старый startup меняет публичные настройки бота; SQLite хранится локально. Исправления новой платформы выполняются отдельно, а не выкатываются поверх Render.

Новый проект использует D1 batch + SQL-триггеры; BEGIN IMMEDIATE из Python не переносится механически. Все неизвестные имена/длительности/часы хранятся в изменяемых демоданных. Не заменять реального сотрудника переименованием старого профиля.

## Как продолжать

Прочитать этот файл, cloudflare/README.md и cloudflare/OPERATIONS.md, сверить git status и remote ветку. Не создавать новый проект. Запуск: из cloudflare pnpm install --frozen-lockfile, pnpm check, pnpm test, pnpm db:local, pnpm seed:local, pnpm dev. Локальный UI fixture и ограничения описаны в README. Ближайший шаг: завершить вход Wrangler после Authorize, создать отдельную удалённую D1, применить обе миграции и только seeds/demo.sql, развернуть основной Worker с пустым allowlist и проверить HTTPS/каталог/отказ защищённых запросов. Если OAuth истёк, повторить официальный вход; не извлекать браузерные cookies. При командах входа использовать XDG_CONFIG_HOME=work/cloudflare-auth (абсолютный путь вне репозитория), NODE_USE_SYSTEM_CA=1; не отключать TLS. Затем продолжить оставшиеся функции.

После каждого завершённого блока обновлять журнал и отправлять код/журнал в эту же ветку. Не отмечать описанный тест выполненным, не выдавать локальный тест за живой Telegram/облачное развёртывание. Готовность демо и production различать явно.
